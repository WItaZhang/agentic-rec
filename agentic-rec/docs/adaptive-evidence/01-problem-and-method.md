# 01 · 研究问题与方法

[返回设计入口](README.md) · [下一篇：数据与评估](02-data-and-evaluation.md)

## 1. 任务定义

对用户 `u` 在时间 `t` 的一次请求，输入为：

- `H(u,t)`：严格早于 `t` 的可见交互前缀，包括时间与反馈类型。
- `C(u,t)`：冻结的候选物品集合，包含基础模型得分和稳定的基础排序。
- `E(t)`：可查询的历史证据库，受时间、字段与候选访问约束。
- `b`：剩余资源预算。

系统输出 `C(u,t)` 内的 Top-K 排序。离线评估器独立保存目标 `y(u,t)`；规划器、工具、特征代码、缓存和提示词均不能读取它。

初期研究固定候选上的排序决策。检索用户历史和商品信息称为**证据检索**；生成候选商品称为**候选召回**。两者在接口、日志和报告中使用不同名称。

主实验预测下一个满足正反馈定义的、用户此前未交互的物品。正反馈阈值、重复消费排除规则和目标可见范围见 [数据协议](02-data-and-evaluation.md)。这评价的是观测数据上的预测能力，不等同于在线点击率提升。

## 2. 为什么需要自适应

一个固定方案可能总是读取近期行为、长期历史、商品属性和评论，再多轮分析。但额外信息可能重复、过时、不相关，且会占用上下文和调用预算。

本项目研究三个连续的问题：

1. 什么信息在当前数据和模型下有帮助？
2. 这种帮助能否通过请求时可见的特征预测？
3. 有了这种预测，是否能减少无用调用而保留排序质量？

不要先假设稀疏用户一定需要更多信息，或兴趣变化一定要求长期记忆。用户组分析的意义就是检查这些直觉是否成立。

## 3. 第一版：学习选择证据方案

先定义少量可以完整枚举的方案，控制实验成本和归因难度。

| 方案 | 执行内容 | 最终排序 |
|---|---|---|
| R0：base | 不新增文本证据 | 基础模型排序，零 LLM 调用 |
| R1：recent | 读取近期行为 | 一次 LLM 重排 |
| R2：recent + long | 近期行为 + 与候选/近期兴趣相关的长期行为 | 一次 LLM 重排 |
| R3：recent + metadata | 近期行为 + 候选属性 | 一次 LLM 重排 |
| R4：full | 近期行为 + 长期行为 + 候选属性 | 一次 LLM 重排 |

所有 LLM 方案看到相同的候选 ID 映射、最低限度的候选身份信息和基础分数（是否提供分数作为固定实验条件）。R3/R4 的“属性”必须是超出公共输入的额外字段，避免把同一信息重复计为工具贡献。

第一版控制器对请求特征 `x(u,t)` 选择方案 `r`。它是**请求级路由**，不是在每个工具结果后重新规划。实现到这里即可形成一个完整、可评估的阶段成果。

### 3.1 可观测特征

| 特征类别 | 例子 | 约束 |
|---|---|---|
| 历史数量 | 交互数、正反馈数、近期窗口事件数 | 仅前缀；不能用完整生命周期计数 |
| 时间分布 | 距上次交互时间、近期行为密度 | 时间单位统一；缺失显式编码 |
| 偏好分布 | 类别集中度、近期与长期类别分布差异 | 类别来源和时间假设记录；“差异”只是兴趣变化代理 |
| 基础排序 | Top-1/Top-2 分数差、Top-K 分数离散程度 | 分数不是校准概率；归一化参数在训练期拟合 |
| 候选属性 | 可用字段比例、品类多样性、训练期流行度 | 获取这些特征的计算和查询也计入成本 |
| 证据状态 | 已获取证据长度、重复率、缺失率 | 第一版只能用执行前可知的部分 |

不能使用目标是否在候选中、目标原始名次、执行后的真实 NDCG、目标评论或未来兴趣标签作为推理输入。按目标流行度做事后诊断可以，但不能将目标信息送入控制器。

### 3.2 训练标签与模型

在单独的 `policy_train` 时间段，对同一训练请求执行 R0–R4，得到：

```text
request_id | route | quality | input_tokens | output_tokens | latency_ms | status
```

对多个预算权重 `lambda`，可以构造：

```text
utility(request, route) = NDCG@K(request, route)
                          - lambda * normalized_resource_cost(request, route)
```

资源成本首选一个清楚定义的标量（例如固定价格表下的调用金额），并另外报告输入/输出 token 和延迟。不能将毫秒、token 和工具次数直接相加；归一化尺度、权重和价格表在训练/验证期冻结。

建议比较两种轻量学习方式：

1. **方案分类**：预测效用最高的方案。对近似并列结果使用冻结的容差，优先较便宜的方案。
2. **逐方案收益回归**：分别预测相对 R0 的质量差与资源成本，再依据预算选择。它比硬标签更能保留“多个方案差不多”的信息。

先用线性/逻辑回归做基准，再用梯度提升树。是否使用 LightGBM 由实现阶段的依赖和验证结果决定，不预先写成已采用的方法。小型 MLP 不是必要前置项。

排序指标对单个样本很稀疏，LLM 输出也可能波动。先查看标签覆盖、方案胜出比例和重复运行稳定性；训练用户权重避免活跃用户支配。若标签主要是噪声，改用更稳定的分组策略或增加训练样本，而不是直接上复杂模型。

### 3.3 策略训练的时间顺序

- 基础推荐模型在 `base_train` 内完成训练及内部时间验证。
- 该模型冻结后，在更晚的 `policy_train` 生成方案结果与控制器标签。
- 控制器训练、归一化、证据选择器拟合只使用允许的训练部分。
- 在 `validation` 选控制器超参数、阈值、预算点和提示词版本。
- 冻结后只在 `test` 评估一次主配置；测试标签由独立评估器使用。

这一四段式设计避免控制器只学习基础模型在自己训练交互上的过度乐观表现。扩展为滚动交叉拟合时，每一折也必须遵循时间顺序。

## 4. 第二版：逐步获取证据与停止

只有当第一版发现可利用的差异后，才增加基于观测结果的多步决策。

### 4.1 状态

`state = (request_features, candidate_summary, acquired_evidence, action_history, remaining_budget)`

每个证据对象带有来源、事件时间、可见性截止点、截断状态和稳定 ID。控制器看到摘要统计或经过约束的证据文本，不能直接访问未获取的全文。

### 4.2 动作

| 动作 | 参数 | 返回结果 | 有效性约束 |
|---|---|---|---|
| `GET_RECENT_HISTORY` | 窗口/条数档位 | 带时间的近期行为 | 严格早于请求时间，按固定规则排序 |
| `GET_LONG_HISTORY` | 查询方式、条数档位 | 相关长期行为 | 只用当前证据/候选构造查询，排除已取证据 |
| `GET_ITEM_METADATA` | 候选子集、字段组 | 属性与缺失标记 | 请求 ID 必须属于冻结候选，字段在白名单内 |
| `GET_ITEM_REVIEWS` | 候选子集、数量档位 | 历史评论证据 | 后续扩展；评论早于请求，不能返回目标评论 |
| `FINALIZE` | 无 | 使用当前证据做一次重排 | 预留最终调用预算；验证结果属于候选集合 |
| `RETURN_BASE` | 无 | 原始基础排序 | 预算不足或无需 LLM 时可终止 |

反思/核验先作为独立实验动作，明确它是否新增事实、是否另调 LLM。不要把纯粹改写已有文本与获取新证据混为一类。

### 4.3 决策规则

可从“预测增量收益是否超过增量成本”开始：

```text
choose action maximizing predicted_gain(state, action)
                         - lambda * predicted_incremental_cost(state, action)
if no valid action has positive expected net value:
    finalize with available evidence, or return base when no call is affordable
```

`predicted_gain` 是基于训练期执行结果拟合的估计，不是推理时读取真实指标。增加证据并不保证当前排序变好；训练标签应使用同一终结流程的对照结果。

一种有限成本的标签构造方式是：从训练期预定义的证据状态出发，比较“现在终结”和“执行某动作后终结”。它只学习一步前瞻，不应宣称为全局最优规划。需要长程决策时，再比较受限的两步枚举或其他方法，并计入标签生成成本。

### 4.4 终止与失败

- 最大工具步数与总预算同时约束，达到任一上限立即终结或回退。
- 每次动作前预留最终输出调用的预算；不能把全部预算花在读证据上。
- 对重复请求相同证据使用可追踪缓存；禁止无信息增益的无限循环。
- 空结果、超时、非法参数和模型拒答都有结构化状态，计入分母与成本。
- 输出出现重复/池外 ID 时执行固定修复规则；修复后仍不足则按基础顺序补齐。

## 5. 证据组织也是实验变量

默认将证据按来源和时间分组，保留可引用的事件 ID，限制每类 token 配额。

比较不同记忆组织方法时，要控制总输入预算：最近 K 条、时间衰减选择、相关性检索、压缩摘要。摘要的生成模型、调用成本和可见性截止点都必须记录。若收益仅来自输入变长，应明确说明。

第一轮不同时优化证据检索器、控制器、LLM 提示词和推荐模型。先冻结其余部分比较证据方案，再学习选择策略，以减少归因混乱。

## 6. 上界诊断与继续条件

在训练/验证阶段统计“每请求最佳方案”相对最佳固定方案的差异，可以估计方案选择的潜在空间。但它读取真实目标，只能作为**事后上界诊断**。

该诊断还有两个限制：选择多个有噪声结果中的最好值会产生乐观偏差；有限方案的最佳值也不是所有可能策略的理论上界。使用独立重复结果检查稳定性，并明确图表标签。

若没有明显的可利用空间，就不训练控制器。若有空间但请求特征无法预测，则讨论需要哪些额外可观测信号，而不是把测试答案变成特征。
