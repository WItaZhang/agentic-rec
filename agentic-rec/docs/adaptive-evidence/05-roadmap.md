# 05 · 分阶段实现路线图

[返回设计入口](README.md) · [上一篇：实验](04-experiments.md) · [下一篇：相关工作](06-related-work.md)

按里程碑推进，不预设必须在多少天内完成。每次工作尽量只完成一个可以运行、检查并留下产物的小步骤。下面所有未勾选项都是待办；设计文档落地不代表实验完成。

## 总览

| 阶段 | 核心交付 | 依赖 | 继续条件 |
|---|---|---|---|
| M0 | 复现已有 MovieLens 基础 | 现有 PR #1 | 数据、指标和运行产物可信 |
| M1 | ItemKNN + Amazon 数据画像 + v1 协议 | M0 | 候选召回覆盖可用，泄漏测试通过 |
| M2 | 真实 LLM 单次重排与证据对照 | M1 | 资源统计完整，额外证据的价值可判断 |
| M3 | 固定方案矩阵与异质性报告 | M2 | 不同请求确有不同方案收益的空间 |
| M4 | 规则、随机和学习路由 | M3 | 对照充分，路由结论有统计支持 |
| M5 | 可选逐步调用与停止 | M4 或明确的新假设 | 相对请求级路由存在待解决的问题 |
| M6 | 强基线、稳健性、报告与简历证据 | 主方法阶段稳定 | 所写结论均有对应产物 |

M6 的强基线和计量检查可以提前做。M5 不必完成才能形成一个有价值的项目；完成 M4 并补齐 M6，已经可以写“学习证据方案路由”的成果。

## M0 · 接入并复现已有基础

检查时 [PR #1](https://github.com/WItaZhang/agentic-rec/pull/1) 提供了真实数据基础和聚合运行记录，但本设计工作没有重新运行其数据实验，也没有合并它。

- [ ] 检查 PR 的最新状态与实现提交，选择已合入代码或明确检出的实验分支。
- [ ] 按原文档用 `uv.lock` 准备环境，不改变原协议。
- [ ] 获取原始数据并检查哈希；保持原始文件只读。
- [ ] 复现 Popularity，核对原报告的用户数、目标数、冷用户/冷物品计数与指标。
- [ ] 改种子/运行目录做一次确定性复现检查，确认无意外覆盖。
- [ ] 给已有协议标记版本；保留其固定历史、多正例定义。

**验收**：同一配置可重复产生一致的确定性结果；协议说明与实际代码一致。

**产物**：运行目录、复现记录、任何差异的解释。

**暂不增加**：LLM、控制器、用户模拟器。

## M1 · 常规推荐与真实时间协议

建议拆成三个小提交。

### M1a：ItemKNN

- [ ] 在现有 MovieLens 协议下实现训练期 ItemKNN。
- [ ] 将相似度、邻居数、反馈权重、归一化和冷启动回退写入 YAML。
- [ ] 检查训练只读 `base_train`，相似度不包含 held-out 交互。
- [ ] 用已知小例子验证分数和排序，再与 Popularity 比较。

### M1b：Amazon 数据画像

- [ ] 选择候选品类并记录官方来源、版本、文件哈希和字段映射。
- [ ] 只基于训练期覆盖比较品类的历史长度、商品文本缺失和内存需求。
- [ ] 明确评分阈值、去重、重复消费与时间单位。
- [ ] 冻结第一品类及四段时间边界。

### M1c：逐事件协议

- [ ] 实现请求/标签隔离、全局时间视图和同时间戳批量更新。
- [ ] 冻结候选宇宙与请求候选清单；不注入正例。
- [ ] 实现冷用户、冷物品、OOV 历史、缺失元数据计数。
- [ ] 实现单目标指标、用户宏平均与分母审计。
- [ ] 通过未来数据扰动不改变过去输入的测试。

**验收**：能够解释每个请求的可见历史、候选来源和指标分母；样本清单可重建。

**产物**：`dataset_profile.json`、冻结 YAML、split/candidate manifest、指标单元测试和基线报告。

**继续决定**：若候选召回过低，先改善基础模型；如果目标多数为不可召回冷物品，明确调整研究范围并升级协议。

## M2 · 单次重排与完整计量

- [ ] 适配真实数据到候选只读接口；禁止旧工具扩大候选。
- [ ] 扩展 LLM 返回对象，保留真实 usage、响应模型、时间和每次失败尝试。
- [ ] 实现预算预留、解析、确定性修复、超时和基础排序回退。
- [ ] 实现公共候选输入、近期证据、长期证据和属性白名单。
- [ ] 冻结一个 LLM、prompt、输出上限和小规模开发请求清单。
- [ ] 明确填写整轮调用预算后，先跑少量真实调用验证计量。
- [ ] 比较原始排序、近期证据单次重排、充分证据单次重排。

**验收**：一个失败/重试请求也能从日志还原资源使用；所有输出属于原候选；当前目标评论不可见。

**产物**：调用 schema、离线适配器测试、pilot 报告和下一轮预算估算。

**继续决定**：若文本收益尚不明确，先排查和重复开发实验，不进入付费全量路由标签生成。

## M3 · 固定方案与收益分析

- [ ] 在训练/验证阶段执行有限方案 R0–R4，保存完整结果矩阵。
- [ ] 为高波动方案增加小规模独立重复，检查胜出标签的稳定性。
- [ ] 比较最佳固定方案与事后方案选择诊断，记录乐观偏差限制。
- [ ] 检查历史长度、偏好差异、基础分数差、属性缺失与收益的关系。
- [ ] 做控制信息预算的长期历史/元数据消融。
- [ ] 记录方案标签生成的总成本。

**验收**：可以回答“哪类请求在哪个方案下受益或退化”，并显示分组样本量和不确定性。

**产物**：方案结果表、证据消融图、分组报告、是否值得学习路由的决定。

**继续决定**：若同一方案稳定占优，先交付固定方案；若差异有空间但不稳定，扩大/改进训练证据，不使用测试集找规律。

## M4 · 学习请求级路由

- [ ] 固定特征 schema，确认每个特征推理时可获得，计入其开销。
- [ ] 实现规则路由、固定种子随机路由和线性模型。
- [ ] 再实现一种树模型作为候选，完整保存训练参数和环境。
- [ ] 使用 `policy_train` 拟合；在验证集选阈值、成本权重和预算点。
- [ ] 对比分类和收益回归，检查路由标签不平衡与近似并列情况。
- [ ] 预先冻结主要比较、质量容差、置信方法和最终测试清单。
- [ ] 在测试集运行一次主矩阵，生成实际质量—成本曲线。

**验收**：学习、规则和随机分配使用同一信息范围；成本不是简单调用步数替代；没有测试标签进入决策。

**产物**：控制器检查点、特征清单、冻结协议记录、配对结果和路由分布。

**可写成果**：学习证据获取方案选择及其真实效果/成本结果。不能此时写逐步停止或多步规划已完成。

## M5 · 可选多步决策

- [ ] 明确 P1 哪些不足需要在读到证据后再决定。
- [ ] 定义少量离散动作、有效参数、状态特征和终止条件。
- [ ] 用训练期的一步前瞻对照生成动作收益标签，记录其近似性质。
- [ ] 实现规则停止、固定长度、学习停止及最大步数约束。
- [ ] 检查空结果、重复证据、预算不足与最终调用预留。
- [ ] 与 P1 和强单次重排比较增量收益，单独报告额外训练成本。

**验收**：工具返回的信息确实参与后续动作选择；预算和失败条件可控；相对简单策略的收益有直接对照。

**产物**：状态转移测试、工具轨迹、停止消融、增量质量—成本曲线。

**继续决定**：若没有增量收益，记录后保留更简单的主方法。

## M6 · 完成可信成果

- [ ] 完成合理调参的强序列模型对照，检查候选和重排两部分。
- [ ] 至少完成主要结果的重复/不确定性分析。
- [ ] 按预算增加候选顺序、第二基础模型、第二品类或第二 LLM 中最重要的一个稳健性轴。
- [ ] 公开关键失败案例的抽样规则与经过处理的案例摘要。
- [ ] 写明动态历史、静态元数据、离线日志和 LLM 预训练知识的限制。
- [ ] 形成可复现报告和一个结果到运行产物的 claim ledger。
- [ ] 根据已经完成的层级填写 [简历模板](07-resume.md)，移除所有占位符。

**验收**：第三方可以从 README 找到协议、配置、结果与复现步骤；每个简历数字都有对应产物。

**产物**：聚合报告、图表、复现说明、实验索引、英文项目描述。

## 三种合理停止点

1. **固定证据方案成果**：真实实验发现哪些信息有用，交付效果与成本最合适的固定方案。
2. **请求级学习路由成果**：完成 M4，证明或否定可观测特征分配证据的价值。
3. **逐步 Agent 成果**：完成 M5，进一步验证工具结果驱动的后续选择与停止。

完成层级不同，简历用词也不同。第一种仍能体现实验能力；不必为了使用“Agent”或“RL”字样强行实现无收益复杂度。
