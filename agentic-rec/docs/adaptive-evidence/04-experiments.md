# 04 · 实验计划与结论标准

[返回设计入口](README.md) · [上一篇：实现](03-implementation.md) · [下一篇：路线图](05-roadmap.md)

## 1. 最小对照矩阵

所有主比较共享数据切分、请求清单、候选成员、可访问证据范围、LLM 版本、输出校验与失败回退。不同策略可以选择获取不同证据，但不能独享未来信息或更好的候选。

| ID | 方法 | 用途 | 必做阶段 |
|---|---|---|---|
| B0a | Popularity | 检查数据和指标，冷启动回退参考 | 工程基础 |
| B0b | ItemKNN 原始排序 | 主要传统基线起点 | 第一轮 |
| B0c | SASRec 或另一强序列模型 | 检查 Agent 收益是否只来自过弱基础模型 | 主结论前 |
| B1 | 近期证据 + 单次 LLM 重排 | 最简单文本增强 | 第一轮 |
| B2 | 充分证据 + 单次 LLM 重排 | 检查是否需要复杂编排 | 第一轮 |
| B3 | 固定多步工作流 | 比较固定计算与自适应计算 | 多步阶段 |
| B4 | 请求特征规则路由 | 检查学习是否优于直观规则 | 路由阶段 |
| B5 | 预算相近的随机方案分配 | 检查正确分配是否重要 | 路由阶段 |
| P1 | 学习请求级路由 | 第一版核心方法 | 路由阶段 |
| P2 | 学习逐步取证与停止 | 第二版扩展 | 可选后续 |
| O1 | 看见真实标签后的最佳方案选择 | 仅上界诊断，不是可部署基线 | 训练/验证分析 |

在早期工程实验中可暂时只有 Popularity/ItemKNN，但此时不写“优于强推荐基线”的结论。接入强序列基线后，应在各召回条件内比较路由效果，分开报告候选召回差异。

### 1.1 B2 必须足够强

“充分证据”指所有允许证据类型在合理上下文限制内的确定性组织，不是无上限地塞入全部原始历史。为它提供合理的字段选择、去重和开发集调参。

为区分信息和推理因素，加入一个补充对照：把某个多步方案实际获取的证据汇总后，交给同一模型单次重排。证据生成成本仍计入，不能因为事后复用就声称免费。

### 1.2 固定多步流程的定义

明确每一步是工具查询、LLM 规划、重排还是核验。示例流程为“近期历史 → 长期证据 → 商品信息 → 重排 → 可选核验”。工具可确定性执行；不能把三个数据库查询自动算成三轮模型推理。

B3 与 P2 共享相同工具和最终重排模板。请求级 P1 与逐步 P2 分开命名，不把 P1 的一次路由结果报告为动态停止收益。

## 2. 实验执行顺序

### E0：协议和成本冒烟

- 在离线 fixture 上检查时间、标签和候选隔离。
- 用小样本验证真实模型响应、usage、截断、超时和回退。
- 统计候选召回上限；若大多数目标未召回，先改召回或收窄排序研究问题。
- 检查一个完整请求的所有资源是否都在日志中。

产物：协议测试记录、样本清单、成本估计和继续决定。冒烟分数不作为正式成果。

### E1：证据是否有价值

比较 B0、R1、R2、R3、R4。分析额外历史/属性带来的配对差异，并查看证据长度、缺失率和输出有效率。

如果 LLM 方案普遍差于基础排序，先检查评分约束、ID 映射、候选顺序、长上下文截断和任务定义。检查后仍无收益时，报告这一发现，再决定是否改任务或数据；不要靠不断查看测试集来寻找提升。

### E2：是否存在可学习的异质性

在 `policy_train` 构造请求 × 方案矩阵，统计：

- 每种方案单独的质量与成本。
- 哪些请求上不同方案产生不同结果，差异是否稳定。
- 最佳固定方案与事后方案选择的差距。
- 方案胜出与可观测请求特征的关系。

只看平均值可能掩盖机会；只看最佳案例又会夸大机会。两者都报告，并检查多次模型输出对结论的影响。

### E3：规则与学习路由

使用训练期标签拟合 P1，在验证集选阈值和预算权重，然后冻结。比较 B2、B4、B5、P1 的质量—成本曲线。

随机路由的方案概率在验证集上选择，使预计平均成本接近 P1；测试时按预先冻结的随机种子执行。实际测试成本可能仍有差异，应显示真实值，不能只按“调用次数相同”称为完全成本匹配。

### E4：逐步控制的增量价值

仅在 P1 有可信结果或明确不足时进行。比较固定顺序、固定步数、规则停止、学习停止及工具顺序变体。

检验 P2 是否在读到证据后做出有意义的不同决策，是否优于在请求开始时一次选好方案。若无增量价值，主系统保留 P1。

### E5：稳健性

根据预算按顺序增加：另一个随机种子/模型重复、候选呈现顺序、另一个基础召回器、第二品类、第二个 LLM。每增加一个轴，保持其他变量固定。

跨模型或跨品类结果只有实际跑过才能写进结论；一个品类上的实验仍可以形成明确、有边界的成果。

## 3. 消融矩阵

| 问题 | 对照 | 需要固定的条件 |
|---|---|---|
| 长期行为有帮助吗？ | 去掉长期证据 / 保留长期证据 | 候选、近期证据、最终 LLM |
| 商品属性有帮助吗？ | 基础身份字段 / 扩展属性 | 不能让去属性版本连候选身份也失去 |
| 信息量还是选择方式有效？ | 同 token 预算的最近 K 条、随机历史、相关历史 | 时间可见范围、总输入预算 |
| 摘要是否值得？ | 原始选择片段 / 压缩摘要 | 摘要生成费用和信息长度都记录 |
| 学习控制是否有效？ | 固定、规则、随机、学习 | 实际预算附近的质量与成本 |
| 停止机制是否有效？ | 固定深度 / 规则停止 / 学习停止 | 工具集、提示词、预算上限 |
| 反思是否有效？ | 无核验 / 核验一次 | 原有证据与新增事实分开统计 |
| 基础模型强弱是否决定收益？ | ItemKNN / 强序列模型，各自做同样比较 | 不跨不同候选池直接归因 |
| 属性快照假设是否影响结论？ | 无文本 / 标题类别 / 更多属性 | 同协议且明确字段来源 |

不要把所有组合做笛卡尔积。先跑与核心假设直接相关的对照，再根据未解决问题扩展。

## 4. 分组分析

主分析的组界限在训练/验证期确定并冻结：

- 历史为零、较短、较长；具体阈值由训练分布确定。
- 近期与长期类别分布差异较小/较大；称“偏好分布差异”，不称有真实标签的兴趣漂移。
- 基础排序分数差较小/较大；这是不确定性的代理，不是已校准置信度。
- 商品信息覆盖较低/较高。

目标是否长尾、是否冷物品可以用于事后误差归因，但必须标为依赖标签的诊断，不能成为推理时的分组选择依据。

每组报告用户数、请求数、基础指标、配对差、成本与置信区间。小组样本太少时只给描述性分析。不要看到组内某个提升后，再把这个组临时改成主要结论。

## 5. 实际资源统计

### 5.1 每请求成本

```text
online_cost = feature_computation + policy_inference + evidence_queries
            + LLM_planning + final_reranking + verification + retries
```

各项首先使用自身单位统计，不直接相加为无单位“成本分数”。另用有版本的价格表换算金额，无法计价的本地计算单列设备、耗时与资源。

至少记录输入 token、输出 token、缓存 token、所有调用/尝试数、各类工具次数、端到端延迟、超时与回退率。提供方不返回的字段写未知；字符数不能代替实际 token。

### 5.2 离线开销

单独报告基础模型训练、路由标签生成、控制器训练、画像/摘要生成、embedding 与索引构建。尤其是枚举所有方案生成标签可能比最终服务成本高得多。

给出多个假设服务请求量 `N` 下的摊销：

```text
amortized_cost_per_request(N) = online_mean_cost + offline_cost / N
```

`N` 是部署情景假设，不是实际用户规模。可以比较达到收回训练额外开销所需的请求量，不能用摊销掩盖实际总实验费用。

### 5.3 延迟与缓存

- 冻结并发、超时、重试、输出上限和缓存条件。
- 冷缓存与热缓存分开报告；缓存是否跨用户/方案共享要明确。
- 除请求服务延迟外，单独报告整轮运行墙钟时间。
- 使用交错/随机的评估顺序降低提供方负载波动影响，记录调用时间与提供方版本。
- 不能用离线回放缓存返回的毫秒数宣称真实 LLM 在线延迟。

## 6. 统计与结论

### 6.1 配对比较

相同请求上计算两方法的指标差，按用户聚合。以用户为单位进行配对 bootstrap，保留同一用户的全部请求和对应方法结果。

主指标、主基线、置信水平、预算点和容忍的质量下降幅度在验证结束时预先固定。建议展示 95% 区间；重采样次数由稳定性检查确定，配置示例 2000 次只是起点。

多个种子/LLM 重复先按预定方法聚合，或使用层次重采样；不能把同一用户的重复请求当作完全独立样本增加显著性。

### 6.2 “质量相近、成本更低”的可核对定义

设质量差 `DeltaQ = Q(adaptive) - Q(reference)`，预先定义可接受下降 `epsilon`。只有当所选单侧置信界支持 `DeltaQ > -epsilon`，并且成本差也支持下降时，才能写“在预定容差内保持质量并降低成本”。

“没有显著差异”不等于证明质量相同。样本太少时，写“未能确定差异”而不是“质量无损”。报告实际 epsilon、置信界和样本量。

如果只在相似预算下质量提高，应写相同预算区间的质量差，并同时给出两者实际成本。不用事后挑选恰好有利的预算点作为唯一结果。

### 6.3 多重比较与探索

预先指定一个主要比较，其余列为次要或探索性。大量组件和分组检验时报告多重比较处理方法，或明确只做描述性分析。探索发现需要新的冻结实验确认。

相对改进、绝对差和百分点分开：

```text
relative_gain = (new - baseline) / baseline
absolute_difference = new - baseline
relative_cost_reduction = (baseline_cost - new_cost) / baseline_cost
```

分母接近 0 时避免只报夸张的相对百分比。每个指标表给出原始数值。

## 7. 必交图表

1. **主结果表**：NDCG、HR、候选召回、实际 token、成本、P95 延迟、失败率和样本数。
2. **质量—成本曲线**：固定方案、规则、随机、学习策略的实际点及不确定性。
3. **证据消融图**：同条件下各证据类型和组织方式的贡献。
4. **分组效果图**：预定义用户组中的配对收益与资源分配。
5. **调用分布**：方案比例/工具深度、提前停止与回退频率。
6. **案例表**：成功、退化、无用调用、缺失证据、非法输出的代表案例。

## 8. 失败分析分类

每个失败可标多个原因，但主因规则固定：

- 召回缺失：目标不在候选，重排无法挽回。
- 数据/证据缺失：历史或属性不可用。
- 偏好混淆：长期证据覆盖近期偏好，或相反。
- 文本噪声：评论泛泛、重复、与目标偏好无关。
- 路由错误：选择了低收益/高成本方案。
- 重排错误：证据已充分但排序变差。
- 执行错误：超时、预算耗尽、无效 ID、解析/修复失败。

案例从预定义类别中固定抽样，避免只展示“看起来聪明”的轨迹。保留短证据摘要和可追溯来源，不把用户评论全文复制进公共报告。

## 9. 最终报告模板

```text
Question and hypotheses
Protocol and known limitations
Data coverage and candidate recall
Methods and baselines
Main paired comparisons
Quality–cost tradeoff
Component and information-budget ablations
Predefined subgroup analysis
Failures, null results, and sensitivity
Offline and serving resource accounting
Reproduction instructions and artifact index
Supported claims and unsupported claims
```

没有提升也应完成这份报告。结论可以是“简单固定方案更可靠”“只有某类请求值得额外证据”或“当前特征不足以预测收益”，前提是实验足以支持该判断。
