# 10 · 术语表

按拼音或首字母排序。带 → 的指向本仓库里的对应实现。

| 术语 | 英文 | 含义 |
|---|---|---|
| Agent | agent | 带循环的 LLM：观察、规划、动作、反馈、再规划。→ `Agent` |
| 保留正样本 | held-out positives | 从用户历史里藏起来当标准答案的交互。→ `SyntheticDataset.holdout` |
| 冷启动 | cold start | 新用户或新物品没有历史。 |
| 候选 | candidate | 正在被考虑、尚未最终排序的物品集合。 |
| 候选总线 | candidate bus | InteRecAgent 提出的工具间共享物品集合的机制。→ `ToolContext.candidates` |
| 画像 | profile | 描述"为谁服务"或"扮演谁"的文字。→ `agentic_rec.profile` |
| 记忆 | memory | 活得比一次 prompt 更久的状态。→ `agentic_rec.memory` |
| 反思 | reflection | 从结果里提炼一句可复用的洞见。→ `agentic_rec.reflection` |
| 规划器 | planner | 把观察变成动作的决策过程。→ `agentic_rec.planning` |
| 工具 | tool | Agent 可调用的函数。→ `agentic_rec.tools` |
| 编排器 | orchestrator | 多个 Agent 的组合方式。→ `agentic_rec.orchestration` |
| 环境 | environment | Agent 与用户互动的沙盒。→ `Environment` |
| 轨迹 | trajectory | 一个回合里每一轮的记录。→ `Trajectory` |
| 奖励 | reward | 环境给动作的数值评价，强化学习用。→ `Environment.reward` |
| 协同过滤 | collaborative filtering, CF | "喜欢相似东西的人以后也会喜欢相似的东西"。 |
| ItemKNN | item k-nearest neighbours | 按物品共现相似度做召回的协同过滤。→ `Catalog.similar` |
| 召回 | retrieval / recall | 从海量物品里快速捞出几百个候选。→ `retrieve` 工具 |
| 排序 | ranking | 对候选精细打分。→ `rank` 工具 |
| 硬过滤 | hard filter | 按属性条件直接筛掉不合格物品。→ `filter` 工具 |
| 流行度 | popularity | 按被交互次数排序的兜底策略。→ `popular` 工具 |
| HR@K | hit rate | 前 K 个里至少命中一个正确答案的用户比例。 |
| NDCG@K | normalised discounted cumulative gain | 命中位置越靠前分越高的排序指标。 |
| MRR | mean reciprocal rank | 第一个命中位置的倒数的平均。 |
| 覆盖率 | coverage | 推荐过的不同物品占目录的比例。 |
| 点击通过率 | CTR | 被点击数除以被展示数。 |
| 留存 | retention | 用户是否继续使用平台。 |
| 提示 | prompt | 给 LLM 的输入文字。 |
| ReAct | reasoning + acting | 思考、动作、观察交替的 prompt 格式。→ `ReActPlanner` |
| Reflexion | – | 失败后用文字复盘并存入记忆的方法。→ `SelfCritiqueReflector` |
| 思维链 | chain of thought, CoT | 让模型先写推理步骤再给答案。 |
| 思维树 | tree of thoughts, ToT | 在多条推理分支间搜索。 |
| 先规划后执行 | plan-and-execute | 先写完整计划再逐步执行。→ `PlanAndExecutePlanner` |
| 分层规划 | hierarchical planning | 宏观定策略，微观定动作。→ `HierarchicalPlanner` |
| 感觉 / 短期 / 长期记忆 | sensory / short-term / long-term memory | RecAgent 的三层记忆。→ `HierarchicalMemory` |
| 用户模拟器 | user simulator | 用来替代真人做评测的 Agent。→ `UserAgent` |
| 人设 | persona | 用户模拟器的性格设定。→ `TraitProfile` |
| 从众程度 | conformity | 用户受流行度影响的程度，Agent4Rec 三维度之一。 |
| 经理 / 工人 | manager / worker | 一个 Agent 派活给几个 Agent。→ `ManagerOrchestrator` |
| 提案 / 选择 | propose / select | 几个 Agent 各出方案，一个挑。→ `VoteOrchestrator` |
| 流水线 | pipeline | 前一个 Agent 的输出是后一个的输入。→ `PipelineOrchestrator` |
| Agent 当工具 | agent-as-tool | 把 Agent 包装成工具供另一个 Agent 调用。→ `AgentTool` |
| 监督轨迹微调 | supervised trajectory tuning | 用好的执行轨迹微调模型。 |
| 强化学习 | reinforcement learning, RL | 用奖励信号更新参数。 |
| 奖励模型 | reward model | 给 Agent 行为打分的模型。 |
| LLM 当裁判 | LLM-as-judge | 用 LLM 评价输出质量。 |
| 可验证奖励 | verifiable reward | 能用规则机械检查的奖励，τ-Rec 提出。 |
| pass^k | – | k 次独立运行全部通过的概率，衡量可靠性。 |
| 注册表 | registry | 按字符串名字实例化组件的表。→ `registry` |
| 合成数据 | synthetic data | 带已知隐藏偏好的生成数据集。→ `make_synthetic` |
| Mock LLM | – | 按固定规则回答的 LLM 替身，用于离线测试。→ `MockLLM` |
