# 08 · 代码导读

## 1. 先跑起来

```bash
cd agentic-rec
pip install -e ".[dev]"                 # 无运行时依赖；dev 加 pytest 和 ruff
agentic-rec list                        # 列出所有注册的组件
agentic-rec run configs/interecagent.toml
agentic-rec compare configs/*.toml --users 30
pytest                                  # 33 个测试
```

`compare` 会打印一张表，每行一个配置，列是模拟指标（轮数、点击率、点击通过率、退出率）、离线指标（HR、NDCG）和 LLM 调用次数。**用 mock LLM 时这些数字不能拿来比较论文**，只能证明流程通了。

## 3. 推荐的阅读顺序

**第一步：`core/types.py`。** 十来个数据类，没有任何逻辑。记住 `Observation`（Agent 看到什么）和 `Action`（Agent 做了什么）这两个。

**第二步：`agents/base.py`。** 不到一百行。`act()` 方法就是 07 节那张图。读懂它，整个框架就读懂了一半。

**第三步：`planning/builtin.py` 里的 `ReActPlanner`。** 看它怎么拼 prompt、怎么解析 `Action:` 行、怎么调用工具、怎么把 `Observation:` 追加回去。这是 02 节讲的 ReAct 循环的实现。

**第四步：`tools/base.py` 和 `tools/builtin.py`。** 看 `ToolContext.candidates` 怎么在 `retrieve` 和 `rank` 之间传递。这是候选总线。

**第五步：`memory/builtin.py` 里的 `HierarchicalMemory`。** 看感觉、短期、长期三层怎么升级，`reflect()` 怎么压缩。

**第六步：`orchestration/base.py`。** 看 `AgentTool` 只有二十行，`ManagerOrchestrator` 怎么把工人塞进经理的工具集。

**第七步：`environment/sim.py`。** 看一轮循环：推荐器动作 → 用户反应 → 文字反馈给推荐器 → 奖励记进轨迹。

**第八步：`recipes/build.py`。** 看配置里的每个键怎么变成对象。`_agent()` 函数是配置到 Agent 的唯一入口。

## 4. 一个具体例子：跟踪一次推荐

以 `configs/interecagent.toml` 为例，`system.env.run(...)` 里发生了什么：

1. `Environment.run_episode` 造一个 `Observation(user=用户记录, messages=[])`。
2. `RecommenderAgent.act(obs)`：
   - `HistoryProfile.render` 产出"用户 u3，最近看了 X、Y、Z，主导类型是科幻和动作"。
   - `WindowMemory.render` 产出最近二十条记录（第一轮为空）。
   - `ReActPlanner.plan` 开始循环：
     - LLM 写 `Action: history`，工具返回历史；
     - LLM 写 `Action: filter`，工具按条件过滤，写入候选总线；
     - LLM 写 `Action: retrieve`，item-kNN 召回，覆盖候选总线；
     - LLM 写 `Action: rank`，排序候选总线；
     - LLM 写 `Final Answer: i17, i42, ...`。
   - 解析出物品 ID，返回 `Action(RECOMMEND, [...])`。
3. 环境把 ID 换成物品对象，交给 `UserAgent.react(items)`。
4. `PreferenceUserPolicy.decide` 按隐藏偏好算每个物品的亲和度，决定点击、跳过或退出。
5. 环境把用户反应写成文字，调用 `recommender.feedback(text)`：
   - `SelfCritiqueReflector.reflect` 让 LLM 复盘，返回一句洞见；
   - 洞见以 `kind="insight"` 写进 `WindowMemory`。
6. 下一轮，`WindowMemory.render` 会把这句洞见带进 prompt。

用真实模型时，第 5 步的洞见会真的影响第 6 步。用 mock 时，洞见是一句固定文字，mock 也不看它，所以消融实验里"有无记忆"数字相同。这是预期行为，`examples/03_ablation.py` 末尾有说明。

## 6. 怎么改

**接真实模型**：把 `MockLLM()` 换成 `OpenAICompatibleLLM(model="gpt-4o-mini")` 或 `AnthropicLLM()`，环境变量里放 key。命令行加 `--llm openai`。

**接真实数据**：写一个函数，返回 `Catalog(items)` 和 `list[User]`，再调用 `catalog.fit_interactions(...)` 算共现。`data/synthetic.py` 是模板。

**加一个组件**：继承对应基类，加装饰器注册，写一个测试。见 `examples/04_custom_component.py` 和 `CONTRIBUTING.md`。

**加一篇论文**：在 `docs/component-matrix.md` 加一行，在 `docs/survey.md` 对应年份加一段，`references.bib` 加条目，能表达的话在 `configs/` 加一个 TOML。

## 7. 测试在测什么

- `tests/test_core.py`：注册表、数据类、四种记忆的行为。
- `tests/test_components.py`：物品库的过滤 / 搜索 / 相似，工具间候选总线传递，五种规划器都能跑，反思器，两种用户策略。
- `tests/test_system.py`：指标计算的精确值，十一个配置文件都能建出来并跑完，三种编排器，命令行。
