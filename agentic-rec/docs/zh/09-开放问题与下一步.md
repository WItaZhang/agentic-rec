# 09 · 开放问题与下一步

## 领域的开放问题

1. **模拟器保真度。** LLM 用户太顺从、会泄露知识（Zhu 等，2024）。SimUSER 和 RecoWorld 在人设一致性和流失信号上有改进，但"模拟到真实"的差距对大多数结论来说仍未被测量。

2. **可靠的评测。** τ-Rec 的 pass^k 结果表明单次运行的裁判分数高估了可靠性；可验证奖励需要结构化目录，不是所有领域都有。

3. **成本。** 一个 ReAct 推荐器每个用户每轮要五到二十次 LLM 调用。哪些组件值回票价，很少有人做消融。本仓库的消融示例就是为了让这件事变得便宜。

4. **长期目标。** BiLLP 和 RecoWorld 瞄准留存；大多数基准仍然只打一次性准确率的分。

5. **用户侧的主动权与利益。** iAgent 和 RAH 把 Agent 放在用户一边；平台 Agent 和用户 Agent 该怎么协商，是个开放的设计问题。

6. **信任与安全。** 通过物品文本做提示注入、曝光不公平、解释的鲁棒性（RobustExplain，2026）才刚开始被研究。

## 本项目的下一步

按投入从小到大：

| 方向 | 要做什么 | 意义 |
|---|---|---|
| 接真实模型 | 用一个便宜模型跑 `examples/03_ablation.py` | 第一次得到有意义的消融数字 |
| MovieLens 加载器 | `Catalog` + `list[User]` + 时间切分 | 离线指标可以和论文对上 |
| 向量记忆 | 给 `VectorMemory` 传一个 embedding 函数 | 记忆检索从词袋升级到语义 |
| 真实检索工具 | 继承 `Tool`，包一个双塔或 BM25 | 候选质量决定上限 |
| 对话式动作 | 让规划器学会输出 `ASK`，用户策略学会回答 | 覆盖对话式推荐那条线 |
| 强化学习接口 | 把 `Trajectory` 导出成标准格式 | 接上 2025 到 2026 年的训练范式 |
| 更多论文 | ToolRec、ARAG、AgenticRec 的配置 | 矩阵覆盖更全 |

## 怎么判断自己学会了

能不看文档做到下面三件事：

1. 拿一篇没读过的 2026 年 agentic 推荐论文，十分钟内说出它在九个组件上各是什么选择，属于哪种角色和拓扑。
2. 把这篇论文写成一个 TOML 配置，跑通。
3. 指出这篇论文相对于 04 节里最相近的那篇，真正的增量在哪个组件。
