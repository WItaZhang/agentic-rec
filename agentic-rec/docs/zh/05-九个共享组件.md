# 05 · 九个共享组件

这是本项目的核心结论。把 04 节的系统并排拆开，架构收敛到九个组件。每个组件在多数系统里出现，在少数系统里缺席，而且实现方式只有寥寥几种。

先给一个比喻：把推荐 Agent 想成一个**新入职的客服**。

| 组件 | 客服的对应物 |
|---|---|
| 画像 | 客户档案卡 |
| 记忆 | 工作笔记本 |
| 规划 | 处理问题的套路 |
| 工具 | 可以查的内部系统 |
| 反思 | 下班后的复盘 |
| 动作接口 | 允许做的事：推荐、追问、回复 |
| 协作 | 同事和主管 |
| 环境与优化 | 培训和考核方式 |
| 评测 | 绩效指标 |

---

## 1. 画像（Profile）

*Agent 知道"它在为谁服务"或"它在扮演谁"。*

- **推荐器侧**：目标用户的摘要，包括 ID、属性、最近历史、主导偏好。InteRecAgent 把它存成一段记忆；MACRec 专门派一个用户分析师 Agent 来生成；ARAG 有用户理解 Agent。
- **用户侧**：一个人设。Agent4Rec 的"口味、活跃度、从众程度"三元组被复用最多；RecAgent 用自由文本；SimUSER 从数据里挖自洽人设。
- **变体**：静态（手写或一次生成）、历史派生（每步重算）、特质槽位（结构化字段）。

本项目：`profile` 类别，`none` / `static` / `history` / `traits`。

## 2. 记忆（Memory）

*活得比一次 prompt 更久的状态。*

- **缓冲区 / 滑动窗口**：对话历史和最近动作。Chat-REC、InteRecAgent、几乎所有对话系统。
- **相关性排序存储**：按"相关度 + 新近度 + 重要性"加权检索。Generative Agents 的规则，RecAgent 和 Agent4Rec 沿用。
- **分层**：感觉 → 短期 → 长期，带升级和定期反思（RecAgent）；事实 vs 情绪（Agent4Rec）；个性化 vs 世界知识（RecMind）。
- **物品侧记忆**：AgentCF 的物品描述。
- **参数化记忆**：CoARS 把经验写进权重，把文字记忆当基线。

本项目：`memory` 类别，`none` / `buffer` / `window` / `vector` / `hierarchical`。

## 3. 规划（Planning）

*一步怎么选。*

- **直接**：一次调用，没有循环（Chat-REC）。
- **ReAct**：思考、动作、观察交替（InteRecAgent、iAgent、多数用工具的 Agent）。
- **先规划后执行**：写出计划，逐步执行，失败重新规划（RecMind；InteRecAgent 的 plan-first 模式）。
- **分层**：宏观策略再微观动作（BiLLP），或把任务拆成子任务（LLMCRS、MACRec）。
- **搜索式**：思维树、自我启发（RecMind）。
- **示例增强**：检索相似的已解决案例塞进规划 prompt（InteRecAgent）。

本项目：`planner` 类别，`chain` / `direct` / `react` / `plan_execute` / `hierarchical`。`chain` 是不用 LLM 的确定性工具链，让传统基线也能进这个框架。

## 4. 工具（Tools）

*Agent 去调用而不是自己知道的能力。*

- 传统推荐模型当工具：硬过滤、软检索、排序（InteRecAgent、ToolRec、AgenticRec）。
- 数据访问：类 SQL 查询、物品查询、搜索（RecMind、MACRec 的搜索者、AgentRecBench 的世界 API）。
- 其他 Agent 当工具（MACRec、ARAG、AgentRec）。
- 工具之间的共享状态：候选总线。

本项目：`tool` 类别，`history` / `item_info` / `search` / `filter` / `retrieve` / `rank` / `popular`，共享 `ToolContext.candidates`。

## 5. 反思（Reflection）

*把结果变成可复用的文字。*

- 对轨迹的自我批评（Reflexion；RecMind 的自我启发；InteRecAgent 的规划反思；iAgent）。
- 反馈条件反思（MACRS；BiLLP 的反思者；RecoWorld 的指令式反馈）。
- 双方同时更新的协同反思（AgentCF）。
- 专职反思 Agent（MACRec）。

本项目：`reflector` 类别，`none` / `self_critique` / `feedback`。

## 6. 动作接口（Action interface）

*Agent 能对世界做什么。*

- 推荐器：推荐一个列表、追问、自然语言回复、调用工具。
- 用户：点击、评分、跳过、评论、退出；更丰富的模拟器里还有聊天和发帖。
- 物品：改写自己的描述。

**关键点**：让一个 Agent 成为"推荐器"或"用户"的，是动作空间，不是模型。外面的循环是一样的。

本项目：`ActionType` 枚举；`RecommenderAgent` / `UserAgent` / `ItemAgent` 只是固定了任务和动作空间。

## 7. 协作（Coordination）

*几个 Agent 怎么合起来。*

- 经理与工人（MACRec、AgentRec）。
- 提案与选择（MACRS、MACS）。
- 流水线（平台推荐器再接个人 Agent，如 RAH、iAgent）。
- 群体互动（Agent4Rec、RecAgent）。

本项目：`AgentTool` 把 Agent 包成工具；`ManagerOrchestrator` / `PipelineOrchestrator` / `VoteOrchestrator`。

## 8. 环境与优化（Environment & optimisation）

*循环在哪里跑，什么会随时间变好。*

- 静态离线数据集加保留正样本（2023 到 2024 年多数工作）。
- 带留存信号的模拟用户（Agent4Rec、RecoWorld、SUBER）。
- 强化学习的奖励函数（Rec-R1、CoARS、RecoWorld、RecRM-Bench）。
- 监督微调的轨迹数据（ToolRec、AgenticRec）。

本项目：`Environment` 每轮同时产出文字反馈（给反思用）和标量奖励（给强化学习用）。训练循环本身不在包内。

## 9. 评测（Evaluation）

- 保留交互上的排序指标（HR、NDCG、Recall、MRR）。
- 模拟器指标（点击、退出前轮数、留存、多样性、茧房程度）。
- LLM 当裁判评对话质量，可靠性有已知问题。
- 目录谓词上的可验证奖励和 pass^k 可靠性（τ-Rec）。
- 标准化 Agent 基准（AgentRecBench、RecRM-Bench）。

本项目：`ranking_metrics` 和 `simulation_metrics`。

## 四条观察

对照 06 节的矩阵，可以得出：

**观察一：循环是共通的，组件是可选的。** 每个系统都有"感知、规划、动作"；多轮的系统都有某种记忆；用工具的系统都有候选传递机制。但没有任何一个组件在所有系统里都出现。Chat-REC 没有记忆和工具；Agent4Rec 的推荐器没有 LLM；ItemKNN 基线根本没有规划器。这就是"可选参数的框架"而不是"固定流水线"的形态依据。

**观察二：差异集中在三处。** 论文之间主要在（a）记忆怎么组织、反思什么时候写入，（b）规划怎么分解，平铺、分层还是多 Agent，（c）Agent 怎么优化，prompt、微调还是强化学习。工具套件、画像、评测协议在各论文之间几乎相同。

**观察三：多 Agent 就是把 Agent 当工具的单 Agent。** MACRec 的经理是一个 ReAct Agent，它的工具恰好是别的 Agent；MACRS 的选择器是对提案的排序。循环里没有任何地方需要知道一个工具是检索模型还是另一个 LLM。这一点让整个架构少了一层。

**观察四：领域正在从文字适应转向参数适应。** 2023 到 2024 年靠往记忆里写字来适应；2025 到 2026 年（Rec-R1、AgenticRec、CoARS、RecoWorld）靠对着模拟或真实反馈更新权重，同期的基准论文（τ-Rec、RecRM-Bench）则在解决"反馈可不可信"。文字反思仍然是强基线，也是实践中更便宜的选择。
