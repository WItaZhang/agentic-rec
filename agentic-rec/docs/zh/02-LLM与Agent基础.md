# 02 · LLM 与 Agent 基础

这一节只讲后面会用到的概念，不讲模型内部原理。

## 1. 大语言模型（LLM）

大语言模型是一个"给它一段文字，它接着往下写"的程序。ChatGPT、Claude、DeepSeek、Qwen 都是。关键性质：

- **输入输出都是文本。** 想让它做事，就把任务写成文字（这叫 prompt，提示）。
- **它读过大量文本，有常识。** 知道《盗梦空间》是诺兰拍的科幻片，不需要你告诉它。
- **它没有记忆。** 每次调用都是从零开始，除非你把之前的内容重新塞进 prompt。
- **它不会主动做事。** 你不调用它，它什么都不会发生。
- **每次调用都要钱、要时间。** 一次调用几百毫秒到几秒，价格按字数计。

在本项目里，LLM 被抽象成一个极简接口（`agentic_rec/llm/base.py`）：

```
complete(prompt: str) -> str        # 给一段文字，返回一段文字
chat(messages) -> str               # 给一串对话，返回下一句
```

真实后端有 OpenAI 兼容接口和 Anthropic 接口。测试和示例用一个 `MockLLM`，它不是模型，是一套写死的规则，看到特定格式的 prompt 就按固定套路回答，目的是让整个流程离线也能跑。

## 2. 什么叫 Agent

"Agent"这个词在不同语境里意思差别很大。在本项目和这批论文里，它的意思是：

> **一个带循环的 LLM。** 它不是被调用一次就结束，而是：观察环境 → 思考 → 做动作（可能是调用工具）→ 看结果 → 再思考 → …… 直到任务完成。

三个特征把 Agent 和"单次调用 LLM"区分开：

1. **自主控制流**：走几步、调用哪个工具，由模型自己决定。
2. **有状态**：有跨步骤、跨会话的记忆。
3. **和环境交互**：工具、用户、其他 Agent 的输出会反过来影响它的下一步。

## 3. 四个基础构件

后面每篇论文都在这四个构件上做文章。它们各自来自一篇奠基性的通用 Agent 论文。

### 3.1 ReAct：边想边做

ReAct（Yao 等，2022）规定了一种 prompt 格式：

```
Thought: 我应该先看看用户的历史。
Action: history
Action Input: {}
Observation: [i3] 沉默的地平线 (genre=sci-fi) ...     ← 这是工具返回的，不是模型写的
Thought: 用户偏好科幻，我去检索相似物品。
Action: retrieve
Action Input: {"k": 10}
Observation: ...
Thought: 够了。
Final Answer: i17, i42, i8
```

模型每次只写到 `Action Input` 为止，程序解析出工具名和参数，真的去调用工具，把结果以 `Observation:` 追加到 prompt 末尾，再让模型继续写。循环直到出现 `Final Answer`。

本项目的 `ReActPlanner` 就是这个循环，`MockLLM` 认得这个格式。

### 3.2 工具（tool）：模型不知道的事，让它去查

模型再博学也不知道你们公司的商品库里有什么。所以给它一组**可调用的函数**，每个有名字、说明、参数格式。模型在 `Action` 里写函数名，程序去执行。

在推荐场景里，最重要的发现是（InteRecAgent，2023）：**传统推荐模型本身就可以当工具**。召回模型是一个工具，排序模型是一个工具，硬过滤是一个工具。LLM 负责决定什么时候调哪个、怎么理解用户的话，传统模型负责在几百万物品里算得又快又准。

### 3.3 记忆（memory）：让下一次调用知道上一次发生了什么

LLM 没有记忆，所以要自己实现。最简单的做法是把最近的对话原样塞进 prompt（缓冲区 / 滑动窗口）。复杂一点的：

- **相关性检索**：存很多条，每次按"和当前问题的相关度 + 新旧程度 + 重要性"打分，只取前几条塞进 prompt。这条公式来自 Generative Agents（Park 等，2023）。
- **分层记忆**：感觉记忆 → 短期记忆 → 长期记忆。新观察先进感觉层，重要的升到短期，短期满了就压缩成一句"洞见"存入长期。这是模仿人的记忆结构。

本项目 `agentic_rec/memory/` 里五种实现对应这些做法。

### 3.4 反思（reflection）：从失败里学到一句话

Reflexion（Shinn 等，2023）的想法：任务失败之后，让模型自己复盘这次轨迹，写一句"下次应该怎么做"，存进记忆。下次做类似任务时这句话会被检索出来。这是一种不改模型参数的"学习"，成本极低。

在推荐里，"失败"通常是用户跳过了推荐或退出了平台。本项目 `agentic_rec/reflection/` 有两种：无条件自我批评，和只在负反馈时触发。

## 4. 多 Agent

一个 Agent 不够用的时候，可以让几个 Agent 分工。常见拓扑：

- **经理 + 工人**：一个经理 Agent 负责拆任务和汇总，工人各管一摊。
- **提案 + 选择**：几个 Agent 各出一个方案，一个选择器挑最好的。
- **流水线**：A 的输出是 B 的输入。

本项目有一个很省事的观察：**经理调用工人，形式上和 Agent 调用工具一模一样**。所以把工人 Agent 包装成工具（`AgentTool`），经理就是一个普通的 ReAct Agent。多 Agent 系统不需要单独一套框架。

## 5. Agent 怎么变好

三条路，成本递增：

1. **只改 prompt 和记忆**（in-context）：模型参数不动。2023 到 2024 年几乎所有工作都在这里。
2. **监督微调**：收集好的执行轨迹，让模型模仿。
3. **强化学习**：让 Agent 和环境（真实用户或模拟用户）互动，用奖励信号更新参数。2025 到 2026 年的趋势。

## 6. 一个必须记住的成本事实

一个 ReAct 推荐 Agent 每轮要调用 LLM 五到二十次。用真实模型跑一千个用户的模拟，可能要几万次调用。这是这个领域论文实验规模普遍很小、且很多工作强调"哪些组件值得保留"的根本原因。
