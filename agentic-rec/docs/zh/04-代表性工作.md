# 04 · 代表性工作逐篇讲解

每篇按同一个模板：**一句话**、**要解决的问题**、**怎么做**、**留下了什么**。第一遍只读前两项。年份是首个公开版本的年份。引用编号见 `docs/references.bib`。

---

## 2023 年：奠基设计

### Chat-REC（Gao 等，2023）

**一句话**：让 ChatGPT 对传统推荐模型的候选做重排和解释，并支持多轮对话。

**要解决的问题**：传统推荐系统不会对话、不会解释、冷启动无从下手。

**怎么做**：传统推荐器先出一批候选；把用户画像、历史和候选一起写进 prompt，让 ChatGPT 排序并给理由。用户追问时，把对话历史带上再问一次。没有工具循环，也没有对话之外的记忆。

**留下了什么**：确立了"LLM 作为接口，传统模型作为底座"的基本模板。本项目 `configs/chatrec.toml`。

### RecMind（Wang 等，2023）

**一句话**：第一个完整的推荐 Agent：规划器、记忆、工具三件套齐全。

**要解决的问题**：单次调用 LLM 无法完成需要多步查询和推理的推荐任务。

**怎么做**：规划器支持思维链、思维树，以及论文提出的**自我启发（self-inspiring）**：记录已经探索过的规划分支，避免重复走老路。记忆分**个性化记忆**和**世界知识**两部分。工具包括数据库查询、网页搜索、文本摘要。在评分预测、序列推荐、解释生成、评论摘要四类任务上验证。

**留下了什么**：把通用 Agent 的规划、记忆、工具范式完整搬到推荐里。本项目 `configs/recmind.toml`，使用 `plan_execute` 规划器和 `vector` 记忆。

### InteRecAgent（Huang 等，2023）

**一句话**："LLM 当大脑，推荐模型当工具。"

**要解决的问题**：LLM 不擅长在海量物品里做精确检索和排序，传统模型不擅长理解自然语言意图。

**怎么做**：三类工具，硬条件查询、软条件检索、排序，共享一条**候选总线（candidate bus）**：物品集合在工具之间直接传递，不经过 prompt，省 token 也避免模型抄错 ID。还有用户画像记忆、**动态示例检索**（从相似案例里取几条塞进规划 prompt）、以及工具链失败时的**反思**。

**留下了什么**：候选总线是整个领域被复用最多的工程设计。本项目的 `ToolContext.candidates` 就是它；`configs/interecagent.toml`。

### RAH（Shu 等，2023）

**一句话**：推荐系统、助理、人三方结构，助理站在人这边。

**要解决的问题**：用户对平台推荐的控制力太弱。

**怎么做**：一个个人助理 Agent，感知、学习、行动、批评、反思，替用户过滤和调整平台的推荐。

**留下了什么**：用户侧 Agent 这条线的起点。本项目中最接近的是 `configs/iagent.toml`。

### RecAgent（Wang 等，2023）

**一句话**：用 LLM Agent 造一群会浏览、会聊天、会发帖的模拟用户。

**要解决的问题**：推荐系统研究缺少一个可以随意做实验的"沙盒"。

**怎么做**：每个用户 Agent 有画像、**三层记忆**（感觉、短期、长期，带重要性打分，短期定期反思压缩进长期）、动作模块（浏览、点击、和其他 Agent 聊天、在社交页发帖）。

**留下了什么**：三层记忆结构成为模拟用户的标准配置。本项目 `HierarchicalMemory` 和 `configs/recagent.toml`。

### Agent4Rec（Zhang 等，2024，SIGIR）

**一句话**：一千个从 MovieLens 初始化的生成式用户 Agent，用来回答反事实问题。

**要解决的问题**：推荐算法会不会造成信息茧房？这种问题只能在模拟里回答。

**怎么做**：每个 Agent 有三个性格维度，**口味（taste）、从众程度（conformity）、活跃度（activity）**；记忆分事实记忆和情绪记忆；动作包括看、评分、以及**离开平台**。

**留下了什么**：三维度人格设定被大量复用。本项目 `TraitProfile` 和 `configs/agent4rec.toml`。

### AgentCF（Zhang 等，2024，WWW）

**一句话**：用户和物品都是 Agent，靠互相修改文字描述来实现协同过滤。

**要解决的问题**：协同过滤能不能在文本空间里做？

**怎么做**：每次模拟交互后，**协同反思**同时改写用户和物品的自我描述，让两者对观察到的偏好更一致。

**留下了什么**："物品也可以是 Agent"这个视角。本项目 `ItemAgent` 类。

### iEvaLM 与 LLMCRS（2023）

iEvaLM 用 LLM 模拟用户来评测对话式推荐；LLMCRS 让 LLM 规划对话子任务并为每个子任务调用专家模型。两者是对话式推荐这条支线的早期代表。

## 2024 年：多 Agent、长期规划、工具学习

### MACRec（Wang 等，2024，SIGIR demo）

**一句话**：经理 Agent 把任务派给用户分析师、物品分析师、反思者、搜索者。

**要解决的问题**：一个 prompt 装不下所有职责，分工更清晰。

**怎么做**：每个角色是一个独立 LLM Agent，有自己的 prompt 和工具。经理分解任务、调用角色、汇总。

**留下了什么**：经理与工人拓扑成为默认模式之一。本项目把工人包装成工具，经理就是普通 ReAct Agent；`configs/macrec.toml`。

### MACRS（Fang 等，2024）

**一句话**：多个按对话行为分工的 Agent 各出一个回复，规划器挑一个；负反馈触发反思。

**要解决的问题**：对话式推荐里"该问、该推、该闲聊"的决策很难一次做对。

**怎么做**：询问 Agent、推荐 Agent、闲聊 Agent 各生成候选回复；规划器选择；**用户反馈感知的反思**在用户不满意时修正对话行为规划。

**留下了什么**：提案与选择拓扑，以及"只在负反馈时反思"。本项目 `VoteOrchestrator`、`FeedbackReflector`，`configs/macrs.toml`。

### BiLLP（Shi 等，2024，SIGIR）

**一句话**：把推荐当长期规划问题，宏观规划器定策略，微观规划器落实到物品。

**要解决的问题**：所有系统都在优化"下一次点击"，没人优化"用户三个月后还在不在"。

**怎么做**：**双层规划**。宏观层从长期记忆里决定这一轮的策略（比如"继续投喂主偏好"还是"探索相邻兴趣以免腻"）；微观层把策略变成具体推荐；反思者根据用户反馈更新两层记忆。

**留下了什么**：第一个明确以留存为目标的 Agent 推荐系统。本项目 `HierarchicalPlanner`，`configs/billp.toml`。

### ToolRec（Zhao 等，2024，SIGIR）

**一句话**：LLM 扮演"代理用户"，按属性逐个探索物品空间并调用属性检索工具。

**怎么做**：代理用户在合成轨迹上微调，这是较早的监督轨迹微调工作。

### Rec4Agentverse、SUBER、KuaiSim（2024）

Rec4Agentverse 设想物品成为 Agent 平台上的 Agent；SUBER 和 KuaiSim 是把 LLM 模拟用户（或行为模型）当奖励来源的强化学习环境，把 Agent 模拟器这条线和经典的强化学习推荐接上了。

### "你的模拟器靠谱吗？"（Zhu 等，2024）

**一句话**：系统性检验 LLM 用户模拟器，发现数据泄露、过度顺从、人设不一致三大问题。

**留下了什么**：模拟器文献里被引用最多的警告。任何用模拟用户得出的结论，都要先过这一关。

## 2025 年：基准、环境、用户侧 Agent、强化学习

### iAgent（Bao 等，2025）

**一句话**：一个站在用户这边的 Agent，按用户指令和个人记忆对平台推荐重排，并自我反思。

**要解决的问题**：平台推荐受商业利益和"强势用户"影响，普通用户的真实兴趣被淹没。

**怎么做**：检索指令相关的知识，重排，自我反思修正。本项目 `configs/iagent.toml` 用流水线：平台推荐器 → 个人重排 Agent。

### Rec-R1（Lin 等，2025）

**一句话**：把一个固定的下游推荐器的表现当奖励，用强化学习优化生成式 LLM。

**留下了什么**：不需要人工标注推理数据的闭环训练方式。

### ARAG（Maragheh 等，2025）

**一句话**：把检索增强生成拆成用户理解、自然语言推理、上下文摘要、物品排序四个 Agent。

### AgentRecBench（Zhang 等，2025）

**一句话**：把 Yelp、Goodreads、Amazon 包成带标准 API 的模拟世界，评测 Agent 在经典、兴趣漂移、冷启动三类任务上的表现。

### RecoWorld（Liu 等，2025）

**一句话**：模拟用户在快要流失时发出"指令式反馈"，推荐器结合反馈调整策略，用强化学习迭代。

**怎么做**：**双视图**结构。用户侧评估内容、更新偏好、在参与度下降时给出文字指令；推荐器侧把指令和自己的推理合并。目标是留存。本项目 `configs/recoworld.toml`。

### SimUSER（Bougie 与 Watanabe，2025，ACL 工业赛道）

**一句话**：从历史数据里挖出自洽的人设，配上人设、记忆、感知、大脑四个模块，微观和宏观层面都比前人更像真人。

## 2026 年：可验证评测，从互动中学习

### AgenticRec（Li 等，2026）

**一句话**：推荐等于在一套推荐专用工具上做工具集成推理，两阶段训练。

**怎么做**：第一阶段用隐式反馈激活轨迹；第二阶段在自生成的困难物品对上做渐进偏好精炼。

### CoARS（Wang 等，2026）

**一句话**：Reflexion 式的文字记忆是瓶颈，把交互经验直接写进参数。

**怎么做**：交互奖励从共享轨迹里同时监督推荐器 Agent 和用户 Agent；自蒸馏信用分配把历史变成 token 级训练信号。

**留下了什么**：明确提出"文字反思是基线，参数学习是方向"。

### τ-Rec（Narasimhan 与 Narasimhan，2026）

**一句话**：用目录谓词上的可验证奖励取代"LLM 当裁判"，报告 pass^k 可靠性；前沿模型 pass^1 只有约 57%。

**留下了什么**：量化了"演示很惊艳"和"可以上线"之间的差距。

### RecRM-Bench（2026）

**一句话**：评测奖励模型本身，主张单一结果奖励不够，要衡量指令遵循、意图理解等中间能力。

### 路线图综述（Lin 等，2026）

按自主程度分级，报告单 Agent 系统仍占多数，多 Agent 稳步上升。同期还有 MACS（电商可靠对话推荐的混合多 Agent）、熵引导的多样化偏好引导、ReRec（推理助手的强化微调）、AgenticRecTune（带自演化技能库的多 Agent 系统优化）。
