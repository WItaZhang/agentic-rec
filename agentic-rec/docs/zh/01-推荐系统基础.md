# 01 · 推荐系统基础

## 1. 推荐系统在做什么

打开视频网站首页、电商 App 的"猜你喜欢"、音乐软件的每日歌单，背后都是推荐系统。它要回答的问题只有一个：

> 在成千上万个物品里，**这个用户接下来最可能喜欢哪几个？**

输入是用户的历史行为（点过什么、买过什么、看了多久）、用户属性、物品属性、当前情境；输出是一个**排好序的物品列表**。

这里有几个约定俗成的词，后面会反复出现：

| 术语 | 含义 |
|---|---|
| 用户（user） | 被推荐的人 |
| 物品（item） | 被推荐的东西：电影、商品、歌曲、文章 |
| 交互（interaction） | 用户对物品做过的事：点击、购买、评分、收藏、跳过 |
| 历史（history） | 一个用户过去的所有交互，按时间排列 |
| 候选（candidate） | 还没最终决定、正在被考虑的物品集合 |
| 目录（catalog） | 所有可推荐物品的全集 |
| 冷启动（cold start） | 新用户或新物品没有历史，系统无从判断 |

## 2. 传统做法：召回、排序

工业界的推荐系统几乎都是两段式：

1. **召回（retrieval / recall）**：从几百万物品里快速捞出几百个"大概相关"的候选。速度优先，精度次之。
2. **排序（ranking）**：对这几百个候选逐个精细打分，选出前十个展示。精度优先。

召回常用的方法：

- **协同过滤（collaborative filtering，CF）**：核心假设是"喜欢相似东西的人，以后也会喜欢相似的东西"。最简单的一种叫 **ItemKNN**：统计哪些物品经常被同一批人一起看，用户看过 A，就推荐经常和 A 一起出现的 B。本项目的 `retrieve` 工具就是这个。
- **流行度（popularity）**：谁都在看的东西推给谁都不太错。最简单的兜底，本项目的 `popular` 工具。
- **向量检索**：把用户和物品都变成向量，找距离最近的。深度学习时代的主流，本项目没有实现，留了接口。

排序常用的方法：给每个（用户，候选）对打一个分数，按分数排。分数可以来自协同过滤共现次数、逻辑回归、梯度提升树、深度神经网络。本项目的 `rank` 工具用的是共现分数加流行度先验。

**硬过滤（hard filter）**是另一个常见步骤：用户说"只要喜剧片"，那就先把非喜剧的全扔掉，再召回排序。本项目的 `filter` 工具。

## 3. 怎么衡量好坏

### 离线评测

把每个用户的历史按时间切开：前面的给模型看，最后几个藏起来当"正确答案"（held-out）。模型推荐一个列表，看正确答案有没有出现在列表前 K 位。

| 指标 | 含义 | 直觉 |
|---|---|---|
| HR@K（命中率） | 前 K 个里至少命中一个正确答案的用户比例 | 有没有猜中 |
| Recall@K（召回率） | 正确答案里被前 K 个覆盖的比例 | 猜中了多少 |
| Precision@K（精确率） | 前 K 个里是正确答案的比例 | 推的东西里有多少是对的 |
| NDCG@K | 命中的位置越靠前得分越高 | 不仅要猜中，还要排在前面 |
| MRR | 第一个命中位置的倒数 | 第一个对的出现得多早 |
| Coverage（覆盖率） | 所有推荐里出现过的不同物品占目录的比例 | 是不是总推那几个 |

本项目 `agentic_rec/evaluation/metrics.py` 里的 `ranking_metrics` 就算这些。

### 在线评测和模拟评测

离线指标只能衡量"预测得准不准"，不能衡量"用户用得爽不爽"、"会不会流失"。真实答案要靠上线做 A/B 测试，代价很高。于是有人想：能不能造一群**模拟用户**，让推荐系统和它们互动，看点击率、停留轮数、退出率？这条线在大模型出现后变得可行，是后面 03 节的重点之一。

本项目 `simulation_metrics` 算的就是这类指标：平均轮数、点击率、退出率、平均奖励。

## 4. 传统推荐系统的局限

正是这些局限催生了后面的 Agentic 方向：

1. **不会对话。** 用户说"我想看点轻松的、不要太长的、最好是今年的"，传统系统没法理解自然语言条件。
2. **不会解释。** 只输出分数，不能说"因为你上周看了 X 所以推荐 Y"。
3. **不会用外部知识。** 一部新电影没人看过就没有协同信号，但它的剧情简介、导演、口碑其实都在网上。
4. **只看一步。** 优化"下一次点击"，不优化"用户三个月后还在不在"。
5. **没有工作记忆。** 每次请求独立处理，没有"上一轮用户拒绝了什么"的概念。

## 5. 数据集

领域里常用的公开数据集，后面论文里会反复见到：

- **MovieLens**（ml-100k、ml-1m）：电影评分，最经典的入门数据集。
- **Amazon reviews**（Beauty、Books、Games 等子集）：商品评论和评分。
- **Steam**：游戏。
- **Yelp**：餐厅。
- **Goodreads**：图书。
- **ReDial、OpenDialKG**：对话式推荐专用，含真实对话。

本项目为了不依赖下载，用 `make_synthetic` 生成一个带"真实偏好"的合成电影目录：每个用户有隐藏的类型偏好，历史从这个偏好采样出来。好处是评测时知道标准答案，也能做规则驱动的模拟用户。
